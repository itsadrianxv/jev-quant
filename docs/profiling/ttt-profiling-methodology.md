# Historical TTT profiling protocol

The current offline protocol is documented in
[performance-benchmark.md](performance-benchmark.md), with runnable commands in
[performance-experiments.md](performance-experiments.md).

The artifacts under `baseline/` and `optimization-after/` were generated by the
previous synchronous `jev_bench`. That binary used bounded text logging and
whole-process Callgrind collection. Its post-optimization native run lost latency
records; the reported percentiles describe only records that reached disk.

Those artifacts remain historical evidence for the redundant snapshot-clearing
investigation. They are not baselines for the new measurement-window protocol.
The replacement runner writes fresh experiment directories and does not overwrite
these historical files.

The old live log parser, `scripts/ttt_percentiles.py`, remains available for
operational logs. Its event names do not establish their measurement endpoints:
`ttt_order_round_trip` measures response queue delay, and `ttt_decision_to_order`
measures a portion of decision handling that can emit no request. Consult the
current methodology before comparing any latency numbers.
